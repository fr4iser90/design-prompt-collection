Build a single-file HTML/CSS/JS interface for 'Tremor Log', a server health monitor visualized as a physical seismograph. The core concept is permanence: server errors are recorded as permanent ink traces on a rotating drum, and user annotations are irreversible ink blots.

**Visual Structure & Layout**
The interface must feel like a piece of precision hardware, not a SaaS dashboard. Use a full-viewport layout divided into two primary zones: the 'Drum Chamber' (70% width) and the 'Control Panel' (30% width, right side). 

1. **The Drum Chamber**: A horizontal cylinder representing the server uptime timeline. The background is a textured paper color (#f2f0ec). The drum rotates left-to-right. A virtual pen arm, anchored at the top center, extends down to touch the drum. The pen arm is a thin, dark metal rod (#1a1a1a) with a slight metallic sheen. The ink line drawn by the pen represents server latency. Normal latency is a thin, steady line. High latency causes the line to vibrate violently. Critical errors cause the line to spike sharply.

2. **The Control Panel**: A minimal, flat panel with a matte finish. It contains the brand wordmark 'Tremor Log' in a small, precise font. Below it, a 'Current Status' readout (e.g., 'Stable', 'Spiking') in JetBrains Mono. A 'Drag to Annotate' instruction in Source Sans Pro. No buttons, no cards, no widgets. Just text and a subtle hairline separator.

**Typography & Palette**
- **Background**: #f2f0ec (Off-white paper). Use a subtle noise texture overlay to simulate paper grain.
- **Ink/Text**: #1a1a1a (Near-black). Use for the pen arm, the ink line, and all primary text.
- **Alert/Accent**: #d9534f (Muted red). Use ONLY for critical error spikes in the ink line and the 'Critical' status text. Do not use for UI chrome.
- **Fonts**: 'JetBrains Mono' for all data readouts (latency values, timestamps). 'Source Sans Pro' for labels and instructions. No Inter, Roboto, or system fonts.

**Interaction & Mechanics**
- **The Pen Arm**: The pen arm is interactive. By default, it hovers slightly above the drum. When the user clicks and holds, the pen arm lowers and 'touches' the paper, creating a thick, messy ink blot at the current time position. This blot is permanent. Dragging the pen arm while held moves the blot horizontally, smearing the ink. Releasing the mouse lifts the pen arm back up. 
- **Permanence**: Once an ink blot is created, it cannot be deleted. The user can only add more blots. The ink line itself is generated by simulated data. 
- **Data Simulation**: Simulate server latency using a sine wave with random noise. Occasionally inject 'spikes' (high latency) that cause the pen arm to vibrate rapidly. 

**Motion & Physics**
- **Entrance**: On load, the drum starts spinning slowly, accelerating to a steady speed. The pen arm lowers with a slight mechanical 'clunk' (visual bounce). 
- **Ambient**: The pen arm should have a constant, subtle vibration (1-2px amplitude) to represent baseline noise. The ink line thickness should vary based on the 'pressure' of the vibration (thicker when vibrating more).
- **Interaction**: When dragging to annotate, the ink blot should grow in size and irregularity based on drag speed. Fast drags create long, smeared blots. Slow drags create dense, round blots.

**States**
- **Default**: Drum spinning, pen arm vibrating, thin ink line being drawn.
- **Annotation Mode**: Pen arm lowered, ink blot being created/dragged.
- **Critical Error**: Ink line spikes sharply in red (#d9534f). The pen arm vibrates violently.

**Technical Constraints**
- Use HTML5 Canvas for the drum and ink rendering. 
- Use CSS for the layout and typography. 
- No external libraries. 
- Ensure the ink line persists as the drum rotates (scrolling effect).
- The interface must feel calm and precise, not chaotic. The vibration should be subtle, not distracting.

**Deliverable: single-file HTML/CSS/JS.**
